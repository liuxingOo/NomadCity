# 城市样式牌·特殊行动 实现方案

## Context

基础版审计的 A1 缺口：城市样式牌解锁的「特殊行动」此前未实现，UI 上「特殊行动」按钮被置灰。
用户已逐条口述规则并确认（本方案的 6 张牌效果均按卡面 `card_cp_lv1.jpg` / `card_cp_lv2.jpg` 读图核实）。
本轮目标：把 6 张基础城市样式牌（500–505）的特殊行动做成数据驱动、纯 C# 可 EditMode 测试的功能，并把 UI 按钮接通。

已确认的两处引擎口径（用户拍板）：
- **504「本轮中额外执行 2 次主要行动」**：当轮内**立即连续**执行（用完特殊行动后该玩家在同一轮紧接着再行动 2 次，其间可穿插快速行动），之后才轮到下一位。
- **504/505「使用此行动的轮中不能使用角色牌」**：**仅限该特殊行动所在的那一轮**，下一轮恢复。

## 卡面确认的效果（基础版 6 张）

## 通用机制（已存在的部分，直接复用）

- 标记轨道 `CityPatternState`：I 级 2 格（0=未使用→1=已使用）；II 级 5 格（0=「2」→1=已使用→2=「1」→3=已使用→4=「0」），`ResetForCleanup` 已实现。
- 宣告是快速行动，已在 `DeclareCityPatternCommand` 落地，每次宣告放 1 个标记到格 0。
- 每张样式牌每玩家每回合只能用 1 次特殊行动：`PlayerState.UsedPatternActionsThisTurn` 已存在。
- 特殊行动是**主要行动**（`ConsumesAction = true`），与 `RuleSpec §6.3f / §10.2-4` 一致。

## 实现步骤

### 1. 数据模型（Core/Model）
- `Cards/CardDefinitions.cs`
  - `RewardKind` 新增 4 个节点：`PaySpread = 32`、`PlaceInfluencePerPatternMarkers = 33`、`ExtraMainActions = 34`、`ForbidCharacterCardsThisRound = 35`。
  - `RewardOp` 新增工厂：`PaySpread(total, params options)`、`InfluencePerPatternMarkers(cap)`、`ExtraMainActions(n)`、`ForbidCharacterCardsThisRound()`；并补 `ToString()` 分支。
  - `CityPatternCardDef` 新增字段 `SpecialActionCost` / `SpecialActionEffects`（`IReadOnlyList<RewardOp>`，构造参数追加，默认空）与只读属性 `HasSpecialAction`（效果非空）。
- `Model/GameState.cs`
  - 新增 `ActiveSpecialActionPatternId`（默认 -1，`Clone()` 复制）：模仿已有的 `LastCityMoveRouteId`，作为「当前正在使用哪张样式牌的特殊行动」的通道，供 `PlaceInfluencePerPatternMarkers` 取计数来源。
  - 新增 `CityPatternState PatternStateOf(int cardId)`（把 `DeclareCityPatternCommand` 里私有的 `PatternStateOf` 提上来复用）。
- `Model/CityPatternState.cs`
  - `bool HasUsableMarker(int seat)`：I 级看格 0、II 级看格 0 或 2。
  - `bool AdvanceMarker(int seat)`：把该玩家第一个「可用格」上的标记下移 1 格（0→1、2→3）。
- `Model/PlayerState.cs`
  - 新增 `int ExtraMainActionsThisTurn`、`int CharacterCardBanRound`（0 = 无限制）；同步进 `Clone()` 与 `ResetTurnScopedState()`。
- `Cards/CardCatalog.cs`
  - `BuildCityPatterns()` 给 500–505 录入费用与效果（用上表），`Pattern(...)` 工厂扩展参数。
  - 550–555 企业扩展牌暂不录入（基础版范围，`HasSpecialAction=false` 即不可用）。

### 2. 效果执行（Core/Engine/Effects/EffectResolver.cs）
- `TryApplyBase` 的 `switch` 新增 4 个 case → 各私有 `Try*`：
  - `TryPaySpread`：镜像 `TryGainSpread`，改用 `choices.ChooseResourceSpread` 拿分配，再逐种 `TrySpend`（开发者模式跳过）。
  - `TryPlaceInfluencePerPatternMarkers`：读 `state.ActiveSpecialActionPatternId` 找到样式牌、`CountOf(seat)` 取标记数、夹到 `op.Amount`（封顶 3），再用 `op.Amount = count` 的派生 op 走现有 `TryPlaceInfluence`（`DeployRules`）。
  - `ExtraMainActions` → `player.ExtraMainActionsThisTurn += op.Amount`。
  - `ForbidCharacterCardsThisRound` → `player.CharacterCardBanRound = state.ActionRound`。
- `CostFeasible` 增加 `PaySpread` 分支：`options` 各持有量之和 ≥ `op.Amount` 即可（局部副本试算）。
- 新增公开的费用可行性入口（供命令 `Validate` 复用私有 `CostFeasible`）：`public static bool CanPay(GameState, seat, IReadOnlyList<RewardOp> cost, out string reason)`。
- `EffectChoiceSession.ChooseResourceSpread` 的提示文案按 `op.Kind` 区分「获得 / 支付」（现文案只说「获得」）；`FirstAvailableChoices` 保持「全给第一种」。

### 3. 命令（Core/Engine/Actions/UsePatternSpecialActionCommand.cs，新建）
- 构造：`UsePatternSpecialActionCommand(int seat, int patternCardId, IEffectChoices choices = null)`；`ConsumesAction = true`。
- `Validate`：`ActionRules.ValidateActivePlayer` → 牌在场上 → `card.HasSpecialAction` → `HasUsableMarker(seat)` → 不在 `UsedPatternActionsThisTurn` → 费用可付（`IgnoresCosts` 跳过）。
- `Apply`（顺序固定）：
  1. `state.ActiveSpecialActionPatternId = patternCardId`；
  2. 执行费用：`EffectResolver.Execute(state, seat, card.SpecialActionCost, choices)`；
  3. 执行效果：`EffectResolver.Execute(state, seat, card.SpecialActionEffects, choices)`；
  4. `AdvanceMarker(seat)`；`UsedPatternActionsThisTurn.Add(patternCardId)`；复位 `ActiveSpecialActionPatternId = -1`；
  5. 汇总 `Report`（费用 + 效果两份 `EffectReport` 合并，沿用现有 `EffectReport` 结构）。

### 4. 引擎（Core/Engine）
- `TurnFlow.CompletePlayerAction`：在推进座位前插入——若当前行动玩家 `ExtraMainActionsThisTurn > 0`，`--` 并 **return**（保持 `ActiveSeat` 不变，让该玩家当轮继续行动）；实现「当轮内连续 2 次额外主要行动」。
- `ActionRules` 新增 `ValidateCharacterCardAllowed(state, seat)`：当 `state.Player(seat).CharacterCardBanRound == state.ActionRound` 时返回失败。
- `CharacterCardCommands.cs` 的 `UseCharacterCardCommand.Validate` 调用上述校验（盖放发生在角色牌盖放阶段，不受影响）。

### 5. UI（Assets/_Project/Scripts/UI，仅 Unity 侧可验证）
- `ActionPanel.cs`：新增 `specialActionButton` 字段，事件发 `ModeRequested?.Invoke(ActionMode.SpecialAction)`，加入 `gatedButtons`；把它从 `notImplementedButtons` 移除（`notImplementedButtons` 保留为空数组以兼容场景）。
- `ActionMode` 枚举新增 `SpecialAction`。
- `GameScreenController.cs`：
  - `SetMode`：`SpecialAction` 时 `patternPanel.SetOpen(true)`；`submitPanelUpdate` 里 `patternPanel.Refresh(state, mode == Declare || mode == SpecialAction)`。
  - 样式牌点击回调理：`Declare` 走原宣告流程，`SpecialAction` 走新流程。
  - 新流程**镜像既有的「建设 L4 / 角色牌」会话**：建 `EffectChoiceSession`，lambda 里在状态副本上跑 `UsePatternSpecialActionCommand`（用副本的默认选择器收集候选），`Advance()` 弹 `ChoicePopup` / 点地图收答案；收集完毕后用记录答案正式 `Dispatch` 真正的命令。参考 `GameScreenController.cs:1210-1260`（建设会话）与 `:1629-1680`（角色牌会话）。
  - 加 `SetMode(ActionMode.SpecialAction)` 的按钮锁：选牌阶段锁其他主要行动，仅留「取消」返回（沿用现有 `gatedButtons` / `inAction` 机制）。

### 6. 测试与文档
- 新增 `Assets/Tests/EditMode/CityPatternSpecialActionTests.cs`，覆盖：
  - 6 张牌各一条：费用扣除、效果落地、标记 0→1（II 级 0→1、2→3）、加入 `UsedPatternActionsThisTurn`。
  - 每张样式牌每回合一次（第二次 `Validate` 失败）；无可用标记时失败；费用不足时失败。
  - 500 的 X 计数与封顶 3（I 级多次宣告后 X 随标记数增长，>3 仍为 3）。
  - 502 的 `PaySpread`（0/3、1/2、2/1、3/0 四种分配均可付；不足 3 个时不可付）。
  - 504：用完后 `CompletePlayerAction` 保持当轮座位、额外 2 次用完后恢复正常推进；`CharacterCardBanRound` 生效并被 `UseCharacterCardCommand` 拒绝；收尾清空。
  - 505：连续 2 次免费城市移动。
- 文档：更新 `Doc/RuleSpec.md` §6.3f / §10.2（补 6 张特殊行动的效果与费用口径、502 为城市移动的更正）、`Doc/CardEffects.md` 新增「城市样式特殊行动」一节。
