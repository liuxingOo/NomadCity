# 效果系统最小闭环：or 二选一 + 4 类影响力操作

## Context

复刻《游城拓荒》的项目里，[EffectResolver.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Engine/Effects/EffectResolver.cs) 已实现 §11 的效果序列、条件段/结果段、尽量执行，以及资源/金券/分数/放置影响力等基础效果。但 41 张设施牌录入后暴露出两个缺口，导致 4 张代表性牌的入场效果只能留空：

1. **`or` 二选一**（§11.4 的 Alternative）：现在没有任何数据结构能表达「两个完整效果择一执行」。
2. **三类影响力操作**：拿走场上 1 个影响力、移动 1 个自己的影响力、替换 1 个影响力，`RewardKind` 里都没有。

本次目标（用户已确认范围：**最小闭环优先**）：把这两个缺口补上，让「佣兵指挥部」「护航调度中心」两张牌的效果真正生效；探索、建造、城市移动、条件计数、结算他牌入场效果、传递起始标记、按单价售卖资源等仍在本次范围外，继续留空并登记在文档里。

两条已确认的判据：
- 「替换 1 个影响力」= 移除一个影响力后**在同一个空格**放置一个自己的影响力；若该点停着对手的城市，则只移除、不放置（[CardEffects.md](file:///d:/My%20project/NomadCity/Doc/CardEffects.md#L51) 已确认的口径）。
- 本轮**不做 UI 选点**。现在所有需要选落点的效果（事件牌放置影响力等）都走 `FirstAvailableChoices` 自动取第一个合法目标；本次保持一致，只补 `IEffectChoices` 的接口与默认实现，UI 侧实现留作后续。

## 设计

### 1. 数据模型：[CardDefinitions.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Model/Cards/CardDefinitions.cs)

不改动 `EntryEffects` / `EventOption` 的既有类型（避免 41 张设施牌 + 22 张事件牌的数据全部返工），改为**在 `RewardOp` 上扩展**：

- `RewardKind` 末尾追加 4 个成员：`Alternative = 10`、`RemoveInfluence = 11`、`RelocateInfluence = 12`、`ReplaceInfluence = 13`。
- 新增 `EffectBranch` 类：一段完整效果（`Label` + `IReadOnlyList<RewardOp> Ops`），代表 `or` 的一个分支。
- `RewardOp` 新增只读字段 `IReadOnlyList<EffectBranch> Branches`（仅 `Alternative` 使用；`RewardOp` 从不用作字典键，加一个引用字段安全），工厂：
  - `RewardOp.Alternative(params EffectBranch[] branches)`
  - `RewardOp.RemoveInfluence()` / `RewardOp.RelocateInfluence()` / `RewardOp.ReplaceInfluence()`
- `RewardOp.ToString()` 增补这 4 种的描述（供 HUD 状态行显示）。

### 2. 执行器：[EffectResolver.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Engine/Effects/EffectResolver.cs)

- 把 `Execute` 里的遍历抽成私有 `ExecuteSequence(state, seat, ops, entries, choices, extension, anchorNodeId)`，供 `Execute` 与 `Alternative` 递归复用。
- `TryApplyBase` 新增 4 个 case：
  - `RemoveInfluence`：候选 = 场上所有**非空**影响力槽（含对手的）；交给 `choices.ChooseInfluenceToRemove`；移除即 `Clear` 槽位并把标记退回**其所有者**的 `MarkersInSupply`（沿用 §6.4d 的口径）。
  - `RelocateInfluence`：候选源 = 当前玩家自己占用的槽；候选目标 = `ActionRules.CanPlaceInfluence` 通过的**空**槽；交给 `choices.ChooseOwnInfluenceMove`；清源格、占目标格，**不动 `MarkersInSupply`**（§6.4b 不增减总数）。
  - `ReplaceInfluence`：候选 = 场上所有非空槽 → 交给 `choices.ChooseInfluenceToRemove` → 移除并退回所有者标记 → **对同一槽位**重新跑 `ActionRules.CanPlaceInfluence`，通过才花自己的标记并放置；不通过时只在 `note` 里记「已移除但无法放置」。玩家 `MarkersInSupply <= 0` 时整个效果跳过（§11.3）。
  - `Alternative`：交给 `choices.ChooseBranch`（返回分支下标，`-1` = 无法选择→跳过并记 note）；选中分支后递归 `ExecuteSequence`。沿用「尽量执行」：分支内某条做不了不阻断剩余条目。
- 候选枚举复用现有的 `AddNodeSlots` / `AddRouteSlots` 模式，新增两个私有方法（列出全部占用槽 / 列出自己的占用槽）。
- `CostFeasible` 同步补 `RemoveInfluence`（恒可行）、`RelocateInfluence`（需存在自己影响力且存在合法空格）、`ReplaceInfluence`（需存在占用槽 + 标记够 + 移除后若放置则需合法空格，按「可行即通过」放宽）；`Alternative` 在条件段里按「任一分支可行即通过」处理。

### 3. 选择接口

- `IEffectChoices` 追加 3 个方法（默认实现全在 `FirstAvailableChoices`，一律「取第一个合法项」）：
  - `int ChooseBranch(int seat, RewardOp op, GameState state, IReadOnlyList<EffectBranch> branches)`
  - `InfluenceSlotRef? ChooseInfluenceToRemove(int seat, RewardOp op, GameState state, IReadOnlyList<InfluenceSlotRef> candidates)`
  - `InfluenceMove? ChooseOwnInfluenceMove(int seat, RewardOp op, GameState state, IReadOnlyList<InfluenceSlotRef> sources, IReadOnlyList<InfluenceSlotRef> destinations)`
- 这三个方法是**留给 UI/AI 的接入点**：UI 侧若要实现真正的玩家点选，只需实现 `IEffectChoices` 并在调用 `EffectResolver.Execute` 时传入；引擎与命令层不改。相关调用点已在 [BuildFacilityCommand.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Engine/Actions/BuildFacilityCommand.cs#L86) 与 `ResolveEventOptionCommand`，本轮**不改这两处的调用签名**。
