# 行动事件统一重构（第一批）

## Context

实机测试发现：建设「载具仓库」时选择分支「执行 1 次探索」，界面没有任何提示，资源点被自动选中、事件卡选项自动取第一个、影响力被直接放上。根因是效果结算入口 `EffectResolver.TryExploreOnce` 在引擎内一次性跑完整条探索，绕过了 UI 的探索流程（选点 → 选定航线/路费确认 → 翻事件牌 → 选事件选项 → 放影响力）。

目标：把「行动」抽成可复用的行动事件。操作区按钮和卡牌/企业/样式效果走同一套 UI 流程，效果授予的行动可以携带限制（免费、金券上限、只限自己/他人影响力等）。

已确认的规则决策：

- 效果授予的行动**必须执行**，不能整体取消；没有合法目标时自动跳过并写日志。
- 「移除影响力」只作为效果事件，**不加操作区按钮**（开发者面板提供测试入口）。
- 分两批：第一批 = 框架 + 探索/建设 + 移除影响力；第二批 = 其余四个行动接入 + 全卡面限制梳理 + 手牌区查看。
- 弃牌区按玩家分组展示，保留使用顺序。

## 总体设计

### 1. 挂起行动状态（引擎）

新增 `Assets/_Project/Scripts/Core/Model/PendingAction.cs`：

- `enum PendingActionKind { None=0, Explore=1, Build=2, RemoveInfluence=3 }`
- `enum PendingInfluenceScope { Any=0, Own=1, Others=2 }`
- `struct PendingActionLimits { bool Free; int MaxVoucherSpend; PendingInfluenceScope Scope; }`（`MaxVoucherSpend = -1` 表示不限）
- `sealed class PendingAction { int Id; int Seat; PendingActionKind Kind; int Remaining; PendingActionLimits Limits; int SourceCardId; string SourceLabel; Clone(); }`

`GameState` 增加 `List<PendingAction> PendingActions`、`int NextPendingActionId = 1`，以及：

- `PendingAction FindPending(int seat, PendingActionKind kind)`（取最早一条）
- `PendingAction FindPending(int id)`
- `void ConsumePending(int id)`（`Remaining--`，归零才移除）
- `void DropPending(int id)`

`GameState.Clone()` 深拷贝列表。快照 `GameStateSnapshot` / `GameStateSnapshotCodec` 同步读写，`Version` 10 → 11。

### 2. 效果入队规则

`EffectResolver` 里只有以下奖励会转成挂起行动：`ExploreOnce`、`BuildOnce`、`RemoveInfluence`、`RemoveOwnInfluence`。

- **只在该奖励是当前执行序列的最后一条时入队**（给 `ExecuteSequence` / `ExecuteOption` 传 `allowDefer`，`index == Count-1` 才为 true）。复合效果（如「拿走 1 个影响力并移动」）保持原路径，避免顺序错乱。
- 只在 `Phase == PlayerActions` 时入队；收尾/延迟效果仍走立即结算。
- 入队前用 `PendingActionRules.HasAnyLegalTarget` 检查；没有目标则不建条目，返回带说明的 `EffectReport`（「没有可探索的资源点，已自动跳过」）。
- `EffectChoiceSession` 在状态副本上试跑，挂起只落在副本上，天然不会污染正式状态；预演会「零提问完成」，这是预期行为。
- 原 `TryExploreOnce` / `TryBuildOnce` 保留为立即结算路径（收尾与无 UI 场合），可改名 `ResolveExploreImmediate` / `ResolveBuildImmediate`。

### 3. 限制规则集中一处

新增 `Assets/_Project/Scripts/Core/Engine/Actions/PendingActionRules.cs`，UI 候选过滤与命令 `Validate` 共用：

- `bool HasAnyLegalTarget(state, seat, kind, limits)`
- `bool CanExplore(state, seat, nodeId, limits)`（复用 `ActionRules.IsNodeOpen`、`HasOpponentCity`、资源点指示物、可达航线、路费 ≤ `MaxVoucherSpend`）
- `IReadOnlyList<int> BuildableFacilityIds(state, seat, limits)`（面板空位 + 免费/金券上限）
- `IReadOnlyList<InfluenceSlotRef> RemoveCandidates(state, seat, scope)`
- `CommandResult ValidatePending(state, seat, kind, id)`

新增 `ActionRules.RemoveInfluenceAt(state, slot, choices)`：从 `EffectResolver.TakeInfluence` 提取「退回供应堆 + 持续计谋接管 + 日志」，命令与效果共用。

### 4. 命令与协议

- `ExploreCommand`、`ExploreInfluenceCommand`、`BuildFacilityCommand` 增加 `int PendingActionId = 0`。
- 新增 `RemoveInfluenceCommand(seat, InfluenceSlotRef slot, int pendingActionId = 0)`。
- 新增 `AbandonPendingActionCommand(seat, int pendingActionId)`：仅在「该座位已无合法目标」或开发者模式下通过，用于自动收尾与防卡死。
- 挂起行动对应的命令在 `Validate` 时跳过主要行动名额检查、读取 `PendingActionLimits` 而不是信任调用方参数；`ConsumesAction => PendingActionId == 0`，避免 `GameEngine.Dispatch` 误记主要行动。
- `ActionRules.ValidateMainActionAvailable` 开头：该座位有待办行动时拒绝新的主要行动（`isContinuation` 除外）。
- `EndTurnCommand` / `PassActionCommand` / `AdvancePhaseCommand`：有待办行动时拒绝，防止绕过。
- `RemoveInfluenceCommand` 在 `PendingActionId == 0` 时要求 `state.DeveloperMode`。
- 协议同步：`CommandKind` 增 `RemoveInfluence = 37`、`AbandonPendingAction = 38`；`CommandCatalog` 登记；`CommandDto` 增独立字段 `PendingActionId`（0 = 无）；`CommandWire` 头部加 4 字节并同步 `Write/Read`；`CommandCodec` 编解码相关命令。

### 5. UI 统一入口

`GameScreenController` 改为 `public sealed partial class`，新增 `Assets/_Project/Scripts/UI/GameScreenController.Actions.cs`：

- `private sealed class ActionRequest { ActionMode Mode; int PendingActionId; int Seat; PendingActionLimits Limits; string Source; bool Granted; }`
- `BeginAction(ActionRequest request)`：清掉上一次探索/建设的暂存，`SetMode`，状态行显示「卡牌效果：执行 1 次探索（剩余 N 次）」。
- `TryBeginPendingAction()`：在 `Update()` 里延后一帧启动，避免和弹窗刷新重入；取本机座位最早的挂起项。联机时只有该座位对应的客户端启动，其他端只显示等待提示。
- `CompleteAction()`：清 `activeRequest`；`Remaining > 0` 时再次启动。
- 探索流程参数化：候选改用 `PendingActionRules.CanExplore`；`CommitExplore` / `ExecuteExplore` 传 `pendingId`；确认窗不再提供「放弃这次行动」。
- 建设流程参数化：`buildSeat` 从请求取；`MaxVoucherSpend` 限制金券选项；`DispatchBuild` 传 `pendingId`。
- 「必须执行」：`OnCancelRequested` / `OnModeRequested` / `OnEndTurnRequested` 先检查 `activeRequest?.Granted`，只允许流程内部回退，不允许退出。
- 移除影响力：新增 UI 模式与 `HandleRemoveInfluenceClick`，候选由 `PendingActionRules.RemoveCandidates` 给出，点格子 → `ChoicePopup` 确认 → 派发 `RemoveInfluenceCommand`。
- `MapStateRenderer` 增 `SetHighlightedSlots(IEnumerable<InfluenceSlotRef>)`（复用节点/航道高亮 Ring 的画法）。
- `DeveloperPanel` 增「移除任意影响力 / 移除自己的影响力」测试按钮。

### 6. 手牌区（第二批）

`CharacterHandPanel` 增加「已盖放」「弃牌区」两个按钮；新建只读列表弹窗展示卡面：

- 已盖放：`PlayerState.PlacedCharacterCard`（仅本机座位）。
- 弃牌区：所有玩家的 `DiscardCharacterCards`，按玩家分组、保留列表顺序。
- 复用 `CharacterCardArt` / 卡面图集，不改动弃牌与刷新规则。

## 验证

1. 编译：`Unity 6000.6.0f1` 批处理编译或本机离线编译脚本，八个程序集全部 exit=0。
2. EditMode：`Unity.exe -batchmode -nographics -projectPath "d:\Unity Program\Nomad City The Founders" -runTests -testPlatform EditMode -testResults "Logs\EditMode.xml" -quit`，327 个既有用例 + 新增用例全绿。
3. 实机 Play（必须）：
   - 建设「载具仓库」→ 选「执行 1 次探索」→ 出现选点 → 路费确认 → 事件牌弹窗 → 选选项 → 放影响力；全程无自动选点。
   - 效果给 2 次探索时，完成第一次后自动进入第二次。
   - 没有合法目标时日志出现「已自动跳过」，且不阻塞结束回合。
   - 开发者面板「移除影响力」→ 高亮候选 → 确认 → 标记退回供应堆。
   - 单机热座下每个座位都能正常接管挂起行动。
4. 联机（同机 Editor + 打包 Player）：行动端触发挂起流程，另一端只显示等待，不抢跑；断线重连后挂起项仍在。

## 风险

- `CommandWire` 头部变更：两端必须是同一版本构建，旧包不能互连。
- `ConsumesAction` 条件化遗漏会把效果行动误记成主要行动，用专项测试覆盖。
- 复合效果顺序：已用「仅末条入队」规避，新增带行动的复合卡时必须检查。
- 快照版本 10 → 11：旧快照/旧存档不兼容，联机两端需同时更新。
- UI 重入：挂起行动延后一帧启动，避免与建设/事件的收尾刷新互相覆盖。
