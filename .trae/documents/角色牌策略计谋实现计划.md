# 角色牌（策略 / 计谋）实现计划

## Context

角色牌目前**只有数据壳**：`CharacterCardDef`（[CardDefinitions.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Model/Cards/CardDefinitions.cs#L17-L35)）只有 `Id/Color/Name`，`CardCatalog.BuildCharacters()` 只填名字，没有「策略 / 计谋」效果；`PlayerState` 已有手牌 / 弃牌区 / 盖放牌字段，`CleanupResolver.ReclaimCharacterCards` 也已实现回收，但**没有任何命令能让玩家「盖放」或「使用」角色牌**，界面上的「使用角色牌」按钮还挂在「待实现」里自动置灰。

本轮目标（用户已确认）：把角色牌机制跑通 —— 盖放、使用（策略 / 计谋）、起始玩家连续使用两种效果，并把**基础 5 角色（雷蛇 / 极境 / 德克萨斯 / 锡人 / 坎诺特）×4 色共用的 9 组效果**全部落码，配套 EditMode 测试。手牌 UI 一并写好，场景接线由用户在 Unity 完成。企业扩展（山 / 玛恩纳）不做。

## 已确认的规则约束

- 阶段：`CharacterPlacement`（盖放）→ `PlayerActions`（使用）。
- 「使用角色牌」是**快速行动**（RuleSpec §6.3a）：`ConsumesAction = false`，不占主要行动名额。
- **每人本回合仅用 1 次**；**起始玩家**可连续使用策略与计谋（顺序自选、也可只用其一）；**非起始玩家**二选一（§6.5a / §10.1.2）。
- 起始玩家两种效果之间**不得插入其他主要 / 快速行动**（§10.1.2）。
- 盖放时若手牌为空 → 先把弃牌区全部收回手牌再盖放（§4.2 阶段 1 / §10.1.1）。
- 收尾：本回合未使用盖放牌时，盖放牌与弃牌区一同回手 —— 现有 [CleanupResolver.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Engine/Actions/CleanupResolver.cs#L55-L77) 已实现，**不改**。
- 设施供应区「被拿取 / 移除即补牌至 6」是通用补充规则（RuleSpec §6.4e 补充规则，实现见 [BoardSetup.RefillFacilitySupply](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/Core/Engine/BoardSetup.cs)），德克萨斯策略复用。
- 用户确认（本轮新定）：起始玩家连用采用**两步命令**；坎诺特计谋由**出牌者指定资源种类、各玩家各自收取金券**。

## 实施步骤

### 1. 数据模型（CardDefinitions.cs + CardCatalog.cs）
- `CharacterCardDef` 增加 `StrategyName` / `TacticsName`（牌面名，供 UI 显示）与 `StrategyOps` / `TacticsOps`（`IReadOnlyList<RewardOp>`），构造函数补默认参数以兼容现有调用。
- `RewardKind` 追加 7 个节点（接在 `PlaceInfluenceOnCityMoveRoute = 24` 之后）：
  - `RemoveOwnInfluence = 25`：移除**自己的** 1 个影响力（退回供应堆）。
  - `ChooseLeastHeldResource = 26`：在给定基础资源里选**持有量最少**的一种，获得 `Amount` 个（并列时玩家自选）。
  - `FreeCityMoveOwnInfluenced = 27`：免费城市移动，但候选限制为「与移动城市相邻**且该点有自己影响力**」。
  - `SupplyCardToDeckBottom = 28`：从设施供应区选 1 张，放回设施牌堆**底部**，随后按补充规则补牌至 6。
  - `OptionalChain = 29`：顺序的**可选**步骤（`Branches`），每步先问「执行 / 终止」，任一步终止则其后全部跳过。
  - `RecallDiscardPerCard = 30`：把弃牌区角色牌全部收回手牌；每张在 `Branches` 的两项间二选一执行。
  - `LevyResourceSale = 31`：出牌者选 1 种基础资源，**所有玩家**把该种资源按 `Amount`（金券 / 个）卖光、各自收取。
- `RewardOp` 补对应静态工厂（复用 `Branches` / `SpreadOptions` 承载数据，新增 `RequireOwnInfluence` 之类的字段一律**不加**）。
- `CardCatalog.BuildCharacters()` 按角色名录入上述 9 组效果。

### 2. 效果执行器（EffectResolver.cs）+ 选择接口（EffectChoiceSession.cs）
- `IEffectChoices` 新增 3 个方法（同步实现 `FirstAvailableChoices`、`RecordedChoices`，以及测试内 `FixedChoices`）：
  - `int ChooseResourceType(seat, op, state, IReadOnlyList<ResourceType> candidates)` — 返回下标，-1 = 放弃。
  - `int ChooseSupplyFacility(seat, op, state, IReadOnlyList<int> candidates)` — 从设施供应区选 1 张。
  - `int ChooseOptionalStep(seat, op, state, int stepIndex, string label)` — 0 = 执行该步，-1 = 终止。
- `TryApplyBase` 增加 7 个 case，各写一个 `TryXxx`：
  - `RemoveOwnInfluence`：候选 = `OwnInfluenceCandidates`，走 `ChooseInfluenceToRemove` → `TakeInfluence`。
  - `ChooseLeastHeldResource`：候选 = `op.SpreadOptions` 中持有量最小者（含并列）→ `ChooseResourceType` → `GainResource`。
  - `FreeCityMoveOwnInfluenced`：把 `TryFreeCityMove` 抽成带候选过滤的私有实现（相邻 + 已开放 + 无对手城市 + 目标点有自己影响力），其余步骤（清对手影响力、出发点放置影响力）不变。
  - `SupplyCardToDeckBottom`：`ChooseSupplyFacility` → `FacilitySupply.Remove` → `FacilityDeck.Add`（底部）→ `BoardSetup.RefillFacilitySupply`。
  - `OptionalChain`：逐 `Branch` 调 `ChooseOptionalStep`，返回 0 则执行该分支 `Ops`（用 `ExecuteSequence` 递归），否则 break。
  - `RecallDiscardPerCard`：先把 `DiscardCharacterCards` 全部移入 `HandCharacterCards`，再对每张调 `ChooseBranch`（`Alternative` 的两个分支）执行。
  - `LevyResourceSale`：`ChooseResourceType`（候选 = `ResourceTypes.Basics`）→ 对每名玩家：`count = 持有量`，`TrySpend` 后 `Vouchers += count * op.Amount`（开发者模式下不扣费）。
- 「尽量执行」语义沿用现有约定：做不了只记 note、不中断后续。

### 3. 命令（FlowCommands.cs 或新增 CharacterCardCommands.cs）
- `PlayerState` 新增回合级字段：`CharacterStrategyUsedThisTurn` / `CharacterTacticsUsedThisTurn` / `CharacterSecondEffectPending`；在 `Clone()` 与 `ResetTurnScopedState()` 中同步。
- `ActionRules.ValidateActivePlayer` 增加拦截：该玩家 `CharacterSecondEffectPending == true` 时拒绝其他行动（提示「使用两种效果之间不能插入其他行动（§10.1.2）」）。
- `PlaceCharacterCardCommand(seat, cardId)`：校验 `Phase == CharacterPlacement`、牌在手牌、尚未盖放；`Apply` 时若手牌为空先回收弃牌区，再把该牌移到 `PlacedCharacterCard`。
- `UseCharacterCardCommand(seat, effect)`（`effect ∈ {Strategy, Tactics}`）：`ConsumesAction = false`；校验已盖放、本回合未用完、该效果未用过、非起始玩家不得连用；`Apply` 用 `EffectResolver.Execute` 执行 `StrategyOps` / `TacticsOps`，起始玩家用掉一个后置 `CharacterSecondEffectPending = true`，否则弃牌（`PlacedCharacterCard` → `DiscardCharacterCards`，`UsedCharacterCardThisTurn = true`）。
- `EndCharacterCardUseCommand(seat)`：校验 `CharacterSecondEffectPending == true`；`Apply` 弃牌、清 pending。
- 命令携带 `IEffectChoices Choices`（同 `ResolveEventOptionCommand` / `BuildFacilityCommand` 的写法），供 UI 用 `RecordedChoices` 重放答案。

### 4. UI（需用户在 Unity 接线）
- `ActionPanel.cs`：新增 `characterCardButton` 序列化字段 + `CharacterCardRequested` 事件，并从 `notImplementedButtons` 的「特殊行动 / 使用角色牌」说明中拆出使用角色牌；沿用 `SetLocked` 在子步骤锁其他按钮。
- 新建 `CharacterHandPanel.cs`（仿 [FacilitySupplyPanel.cs](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/UI/FacilitySupplyPanel.cs)）：显示本机手牌角色名 / 可交互，点牌发出选择。
- `GameScreenController.cs`：接线两条流程 —— 盖放阶段点手牌 → `PlaceCharacterCardCommand`；行动阶段点「使用角色牌」→ 选策略 / 计谋 → `EffectChoiceSession` 收集点选 → `UseCharacterCardCommand`；起始玩家用掉一个后弹「继续用另一种 / 结束」→ `EndCharacterCardUseCommand`。效果内点选复用现有 `EffectChoiceSession` + `ChoicePopup`（[GameScreenController.cs#L527-L577](file:///d:/My%20project/NomadCity/Assets/_Project/Scripts/UI/GameScreenController.cs#L527-L577)）。
